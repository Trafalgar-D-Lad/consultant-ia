Bloc 1 — Penser en workflow

Déclencheur→Données→Traitement→IA si utile→Validation→Action→Trace

Cette représentation doit rester lisible par un client non technique. La technologie vient seulement ensuite.

À éviter

Empiler LLM, agents et connecteurs sans besoin métier précis.

À viser

Un flux minimal où chaque étape a une raison et un comportement en cas d’erreur.

Bloc 2 — Les briques techniques

n8nDéclencheurs, logique, connexions, transformations et orchestration.
LLMExtraction, classification, synthèse, génération contrôlée.
APILire ou écrire dans un service de manière structurée.
WebhookRecevoir un événement en temps réel.
Base / tableurStocker un état, une file ou un historique.
Validation humaineBloquer une action sensible jusqu’à confirmation.
Rôle de n8n : il n’est pas « l’IA ». Il orchestre les étapes et fait circuler les données entre les systèmes.

Mini-projet • Partie 1 • Milieu de semaine

Prototype minimal

Construis un workflow de démonstration autour d’un cas simple. Exemple conseillé : note vocale ou texte → extraction des informations → brouillon de devis → validation manuelle.

  • déclencheur fonctionnel ;
  • données d’exemple ;
  • sortie structurée ;
  • une validation explicite ;
  • aucun envoi irréversible automatique.
Objectif : prouver le flux, pas produire une application finale.

Bloc 4 — Fiabilité & erreurs

Questions obligatoires avant livraison

  • Que se passe-t-il si une donnée obligatoire manque ?
  • Que se passe-t-il si le LLM répond dans un mauvais format ?
  • Que se passe-t-il si une API est indisponible ?
  • Comment éviter les doublons ?
  • Comment reprendre un élément échoué ?
  • Comment tracer qui a validé quoi ?

Règle : une automatisation professionnelle doit avoir un chemin d’échec, pas seulement un chemin idéal.

Bloc 5 — Sécurité & données

ValidationContrôle humain pour décisions, facturation et communications engageantes.

Plan BProcédure manuelle disponible si le workflow tombe.
Mini-projet • Partie 2 • Fin de semaine

Workflow fiable + démonstration

Reprends ton prototype et ajoute :

  • validation humaine ;
  • gestion d’au moins 2 erreurs ;
  • journalisation minimale ;
  • données de test normales et anormales ;
  • schéma du workflow ;
  • démo de 3 minutes ;
  • mesure avant/après hypothétique ou réelle.
Critère de réussite : tu dois pouvoir expliquer au client ce qui est automatisé, ce qui ne l’est pas et ce qui arrive en cas d’échec.
